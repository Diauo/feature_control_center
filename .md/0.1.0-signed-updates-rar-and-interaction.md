# 0.1.0：签名更新、RAR 与交互体验

## 1. 变更目标

本次版本解决四个明确问题：

1. 已部署实例已经产生 SQLite 数据后，不能靠覆盖目录修复 Bug；
2. 功能包必须支持 `.rar`，同时不能降低既有归档安全边界；
3. 新增、保存、上传、运行、停止和下载等操作缺少一致、显眼但不打断操作的结果反馈；
4. 登录页视觉和侧栏收放动作不符合当前产品定位。

版本由 `0.0.12` 提升至 `0.1.0`。提升次版本而不是补丁版本，是因为新增了长期兼容的更新包协议、稳定 Launcher 边界和数据库状态模型。

## 2. 没有采用的方案

### 2.1 不挂载 Docker Socket

让 Web 自行拉取镜像或重建容器需要把 Docker Socket 暴露给公网应用。该 Socket 基本等价于宿主机 root 权限，不符合“系统即使被攻破也尽量缩小影响面”的目标。

### 2.2 不直接覆盖 `/opt/fcc`

覆盖当前目录会产生半更新状态，进程正在 import 的代码与磁盘代码也可能不一致。只读镜像层本来也不适合作为可变安装目录。

### 2.3 不在线安装 PyPI 依赖

在线解析依赖不可重复，也会把第三方源故障和供应链变化带到客户现场。更新包必须携带应用及全部间接依赖 wheel，Launcher 使用 `--no-index` 离线安装。

### 2.4 不把签名私钥交给客户系统

服务器只保存 Ed25519 公钥。如果私钥进入镜像或 `/data`，攻破服务器的人就可以为恶意更新签名，签名机制将失去意义。

## 3. FCUP 更新包协议

`.fcup` 是结构受限的 ZIP 容器，根目录只有：

```text
manifest.json
manifest.sig
wheels/*.whl
```

`manifest.json` 使用 UTF-8、键排序、无额外空白的规范 JSON。签名覆盖规范 JSON 的原始字节。清单固定包含：

- 协议版本与产品 ID；
- 目标版本和允许升级的来源版本范围；
- Launcher 协议、Python 主次版本和目标平台；
- 期望的 Alembic 数据库 revision；
- 是否允许保留当前数据库主动回退；
- 应用 wheel、更新说明以及每个 wheel 的路径、大小和 SHA-256。

解析器拒绝未知字段、非规范清单、错误签名、非 wheel 文件、未声明文件、路径穿越、Unicode 路径归一化变化、大小写冲突、加密、链接、特殊文件、异常压缩比、超量条目和不兼容版本。

## 4. 更新执行状态机

```text
READY
  -> PENDING
  -> APPLYING
  -> SUCCEEDED
  -> FAILED / ROLLED_BACK
```

- `READY`：Web 已完成签名、版本、平台和全部文件摘要校验；
- `PENDING`：管理员通过密码复验，SQLite 中取得单实例活动更新约束，并写入待执行控制文件；
- `APPLYING`：Launcher 已停止三个业务服务，重新验证包并开始处理；
- `SUCCEEDED`：迁移、Web 就绪和 Runner/Scheduler 新心跳全部通过，当前版本指针已原子切换；
- `FAILED`：数据库变化前失败，或者无需恢复的控制步骤失败；
- `ROLLED_BACK`：候选版本已经触碰数据库，但失败后成功恢复了备份和旧程序。

活动更新使用 SQLite 部分唯一索引限制为一条。每个包摘要也有唯一索引，避免并发重复登记。

## 5. 稳定 Launcher 边界

Docker 入口仍是基础镜像中的 `fcc-launcher`。Launcher 本身不由 `.fcup` 替换，因此安装失败不会同时破坏负责恢复的代码。它负责：

- Linux 身份与目录权限准备；
- 启动、停止 Web、Runner 和 Scheduler；
- 每两秒写入 Launcher 协议和心跳；
- 消费一次性待更新控制文件；
- 在 `/data/releases` 创建版本隔离 venv；
- 用 SQLite Online Backup API 写入 `/data/backups` 并运行 `PRAGMA integrity_check`；
- 以 `fcc` 身份执行候选版本迁移与预检；
- 检查实际 Alembic revision 是否与签名清单一致；
- 等待 Web readiness 与两个工作进程的新鲜心跳；
- 原子切换 `/data/releases/current.json`；
- 使用 `/data/backups/.update-recovery.json` 处理更新中断。

Launcher 会将控制文件与 SQLite 中的待执行记录逐项比对。文件损坏、包摘要不一致或版本信息被修改时，不会停业务服务：控制文件被拒绝，应用更新退回“已验证”以便管理员重新提交，回退请求则进入失败终态，并记录操作人、来源 IP、请求号和拒绝原因。这样既不执行不可信状态，也不会留下永久占用更新锁的记录。

候选服务通过健康检查后，版本指针和数据库终态写入仍属于切换事务的一部分。只要最终提交没有完整完成，Launcher 会先终止候选 Web、Runner、Scheduler，再恢复更新前数据库与旧版本指针，最后才重新开放旧服务，避免两个版本同时接触同一 SQLite。

基础镜像中的 Python、Launcher、7-Zip、操作系统库和更新公钥不允许由 `.fcup` 自我替换。需要改变这些边界时，应交付新 Docker 镜像，并在停机备份后的受控维护窗口升级。

## 6. 回退语义

两种回退不能混在一起：

- 候选版本安装失败时，还没有对外接管流量，系统恢复迁移前 SQLite 备份和原程序；
- 新版本已经成功运行并产生数据后，管理员主动回退只切换程序，不把 SQLite 恢复到过去，避免抹掉更新后业务记录。

只有制包方确认旧程序能够读取新数据库时，才允许在清单声明 `rollbackCompatible=true`。否则页面不提供主动回退。

## 7. RAR 支持

`rarfile 4.5` 负责静态解析 RAR3/RAR5 元数据，正式镜像内置 7-Zip 26.03 的 `7zz` 解码工具。Docker 构建针对 `amd64` 和 `arm64` 使用各自固定下载地址和 SHA-256，构建阶段校验后才复制二进制。7-Zip 许可证随交付包保存在 `docs/third-party/7zip-license.txt`。

平台拒绝：

- 自解压 RAR；
- 加密 RAR；
- 多卷 RAR；
- 符号链接、硬链接、文件重定向和特殊文件；
- 路径穿越、路径冲突、异常压缩比和超过后台上限的内容。

RAR 仍只是功能包容器。数据源可以是任意文件，平台不解释文件业务内容。

## 8. 前端交互

### 8.1 通知

引入 `vue-sonner`，统一放在右上角，最多同时显示三条。成功提示短暂保留，失败提示保留更久；表单原有的就地错误仍保留，通知不取代可定位的字段错误。

### 8.2 登录页

- 宽屏采用左 65%、右 35%；中等宽度为 55% / 45%；窄屏变成上方视觉和下方表单；
- 左侧为原创哥特建筑线框、低对比酒红和紫色光影；
- `motion-v` 用 MotionValue、spring 和 transform 响应指针，不在每个 pointer event 触发 Vue 组件重渲染；
- 触屏关闭跟随光效，`prefers-reduced-motion` 下关闭非必要动态；
- 密码显示状态使用 Morphicons 的 Eye / EyeOff 平滑变形。

Motion 和进度条需要运行时写入 transform、宽度与 CSS 变量，因此 CSP 的 `style-src` 允许内联样式。`script-src` 仍严格保持 `'self'`，没有加入 `unsafe-inline`；这只放开表现属性，不允许内联脚本执行。

### 8.3 侧栏

- 折叠按钮始终位于同一 DOM 和底部位置，避免键盘焦点跳转；
- 网格列宽、侧栏宽度、内边距、文字和图标使用同一 260ms 缓动；
- 不再用 `display: none` 瞬间切换主要标签；
- 动画期间暂时不弹 tooltip，结束后折叠图标保留文字提示；
- 控制图标使用 Morphicons，系统低动态设置仍然生效。

## 9. 系统更新页面

“系统更新”位于“更新记录”之前，包含：

- 当前版本、运行平台、Launcher 状态和活动任务数；
- `.fcup` 上传与验证反馈；
- 每条更新的来源/目标版本、阶段、持久进度、操作人、来源 IP、更新时间和发布说明；
- 安装前密码复验；
- 可用时的保留数据回退；
- 服务重启期间的自动重连说明。

本地 Windows 开发环境允许验证和展示更新包，但 Launcher 明确显示不可用，不伪装成可执行更新环境。

## 10. 配置与持久目录

新增后台设置：

- `updates.max_package_bytes`，默认 524,288,000 字节，允许 10 MiB 到 2 GiB。

新增目录：

```text
data/updates/inbox
data/updates/control
data/releases
data/backups
```

数据迁移仍必须复制整个 `data` 目录；不能只复制 `fcc.db`。

基础交付版本仍保存在不可变 Docker 镜像内，已经安装的历史版本保存在 `data/releases`，原始签名包保存在 `data/updates/inbox`。回退不依赖甲方手工替换服务器目录。
