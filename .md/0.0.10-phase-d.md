# 0.0.10 阶段 D 改动记录

日期：`2026-09-09`  
版本：`0.0.10`

## 改动目标

在不改变平台业务边界、不修改原 `features/` 素材的前提下，完成阶段 D 的定时任务、跨客户功能复制、运行记录筛选和后台设置闭环。核心目标不是增加“更多按钮”，而是保证所有运行来源最终进入同一套可停止 Runner 和实时日志链路。

## 主要改动

### 后端

- 新增 `scheduled_task`、`scheduler_heartbeat` 模型和 Alembic `0005_phase_d`；
- 新增独立 Scheduler worker、命令行入口和单实例心跳；
- 定时触发使用 `schedule ID + 计划时点` 唯一键防重复；
- 实现默认 60 秒错过容差和明确无补跑策略；
- 手工与定时运行共用输入快照和排队校验；
- 新增定时任务 CRUD 和客户级服务端授权；
- 新增快捷复制，每个目标客户独立事务；
- 目标客户共享不可变代码版本，但从包内默认文件建立独立数据源第 1 版；
- 不复制来源配置、密钥、当前数据源、最长运行覆盖、计划和日志；
- 运行列表新增功能、状态、来源、时间和 request ID 前缀筛选；
- 系统设置新增系统名称、时区、会话期限与 Scheduler 参数；
- 修正运行服务抽取排队逻辑后手工运行审计引用局部变量的问题。

### 前端

- 新增“定时任务”导航和页面；
- 提供每天、每周、每月表单与高级 5 段 Cron；
- 展示时区、下次执行、最近调度结果、累计错过次数和关联运行；
- 功能管理新增多客户复制对话框和逐客户结果；
- 运行记录新增组合筛选面板；
- 系统设置补齐系统、会话和 Scheduler 参数；
- 延续现有 Apple 风格卡片、半透明侧栏、状态标签和响应式布局。

### 运行与交付

- 单容器启动器现在监督 Web、Runner 和 Scheduler；
- Scheduler 使用 `fcc` 用户，功能脚本仍由 Runner 降权为 `fcc-script`；
- 增加 `croniter==6.2.4` 与 `tzdata==2026.3` 固定依赖；
- 版本、Docker 标签、Compose 镜像、README 和本地开发命令更新到 `0.0.10`。

## 未改变的边界

- 不增加商品、库存、失败项或业务补偿模型；
- 不实现失败项重跑；
- 不解析客户数据源内容；
- 不从来源客户复制当前业务数据或密钥；
- 不让 Scheduler 直接启动脚本；
- 不引入 Redis、Celery、外部数据库或其他部署服务；
- 不修改 `features/` 目录。

## 迁移提示

应用启动会自动执行 `0005_phase_d`。升级前仍应停止容器并备份完整 `data/`，特别是 `fcc.db`、WAL/SHM（若存在）和 `instance.key`。日常设置继续从后台维护，不需要新增 Docker 环境变量。
