# 1.0.1：功能上传与运行入口衔接

## 1. 变更目标

功能上传属于管理员操作，实际运行属于客户功能操作，两者保留在各自业务页面没有问题；此前缺少的是页面之间的操作衔接。管理员完成“上传功能 → 运行功能”时只能依靠侧栏往返，页面没有明确告诉用户下一步在哪里。

本次补充双向入口，不搬迁上传表单、不复制运行逻辑，也不改变现有权限边界：

1. 工作台标题区为管理员显示“上传功能”，直接进入功能管理；
2. 功能管理为当前客户的每个已登记功能显示“运行功能”，直接提交任务并打开实时日志；
3. 普通操作员不显示上传入口，因为其没有功能管理权限；
4. 继续沿用顶部当前客户。若处于“全部客户”，功能管理仍要求先选择具体客户后才能上传。

版本由 `1.0.0` 提升为 `1.0.1`。本次不制作或替换桌面交付 ZIP。

## 2. 设计理由

上传包、静态校验、依赖准备和版本切换属于功能注册领域；选择客户功能、确认配置和提交运行属于工作台领域。把两套逻辑放进同一个页面会造成重复状态、重复权限判断和后续维护分叉，因此保持现有页面职责，只增加明确的上下文跳转。

工作台的上传入口放在页面标题区并使用次级按钮，不抢占功能卡“运行”的主操作层级。功能管理的运行入口放在各功能定义卡片上，因为页面可能同时存在多个功能，页面级按钮无法明确要运行哪一个。运行按钮复用现有运行 API，提交成功后直接进入该任务的实时日志页面；功能未准备完成或必填配置不完整时保持禁用并说明原因。

功能管理的上传面板本来就在页面首屏，因此工作台入口不再引入额外弹窗或自动打开系统文件选择器。

## 3. 权限与数据影响

- 工作台“上传功能”使用现有 `session.isAdmin` 判断，只对管理员显示；
- 功能管理路由继续由现有管理员路由守卫保护；
- 功能管理复用现有运行 API，不新增接口，不改变上传或运行请求；
- 不新增数据库字段和迁移；
- 不改变客户、配置、数据源、日志或调度行为；
- 路由跳转保留当前客户选择，用户不需要重新选择客户。
