# 1.0.5 客户交付包

## 变更目的

为 Linux 服务器部署生成一份可独立移交的 1.0.5 交付包。交付物不是项目目录的临时压缩副本，而是由固定白名单重新组装，包含部署入口、完整源代码、生产静态资源、交付文档、功能包示例、OZON 适配包及完整性校验文件。

本次只封装已经验收的 1.0.5 版本，没有修改运行契约或业务功能，因此不另行提升系统版本。交付文档中遗留的 1.0.0 路径、文件名和验证结果已同步到 1.0.5。

## 交付模式

生成工作站没有 Linux Docker Engine，也没有可核验的 1.0.5 Linux OCI 镜像，因此 `DELIVERY-MANIFEST.json` 将本包标记为 `source-build`。目标 Linux 服务器首次执行 `./install.sh` 时，从随包源代码构建 Docker 镜像。

没有放入空镜像、Windows 镜像或改名文件来伪装离线交付。目标服务器应具备 Docker Engine、Docker Compose v2 和构建期间的外网访问能力。若项目以后要求完全离线安装，应在同架构 Linux Docker 构建机生成并验收离线镜像，再重新封装交付包。

## 交付内容

- Linux 一键安装和日常管理脚本；
- 后端、Runner、Scheduler 与前端完整源代码；
- 已构建并同步到后端的前端生产资源；
- 数据库迁移、测试和发布校验工具；
- 管理员、功能包开发、部署、安全、备份恢复、更新回退和故障排查文档；
- 交付验收示例、功能包起步模板、实时日志稳定性测试功能包；
- OZON 在线依赖包和 Linux amd64 离线依赖包；
- `DELIVERY-MANIFEST.json`、包内 `checksums.sha256` 和交付 ZIP 外部 `.sha256` 文件。

运行数据目录、SQLite 数据库、实例密钥、登录信息、客户数据源和历史日志均不进入交付包。

## 尚需在目标服务器验证

Windows 工作站不能替代 Linux 容器验收。接收方首次部署后仍应完成：

1. `./manage.sh status` 和健康检查；
2. 首次初始化、登录和客户切换；
3. 上传并运行“交付验收示例”；
4. 运行“实时日志稳定性测试”，分别验证正常结束和主动终止；
5. 创建备份并校验备份文件；
6. 若接入真实 OZON 业务，使用测试店铺先完成业务侧联调。
