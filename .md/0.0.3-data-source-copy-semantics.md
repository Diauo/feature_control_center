# 0.0.3 — 补全功能复制的数据源规则

## 日期

2026-09-08

## 问题

`0.0.2` 方案已经提出“功能代码版本共享、客户数据源归属于 `customer_feature`”，但快捷复制章节同时写了“默认不复制数据源”和可选“复制来源客户当前数据源”，没有明确说明目标客户的初始数据源从哪里产生。这与数据源默认文件章节存在歧义，也可能导致复制后的功能没有可下载文件，或者误把 A 客户的数据复制给 B 客户。

## 决策

1. 被复制功能继续引用同一个不可变 `feature_version`，代码 ZIP 不重复保存。
2. 功能版本 ZIP 内的默认数据源登记为只读 `feature_version_default_data_source`。
3. 每个目标客户创建自己的 `customer_feature_data_source_revision` 第 1 版，内容来自当前功能版本的默认数据源。
4. 目标客户下载的是自己的当前数据源；复制完成且尚未替换时，其内容等于包内默认文件。
5. 不复制来源客户当前数据源，也不提供普通复制流程中的相关复选框。
6. 每次替换创建新的客户数据源版本，再原子更新当前指针。
7. 创建运行时固化客户数据源版本 ID，Runner 将该版本物化到本次 `request_id` 的独立工作目录。
8. 功能代码升级默认保留客户当前数据源，不使用新包默认文件自动覆盖。
9. 必需数据源缺少包内默认文件时，复制后的功能进入 `WAITING_DATA_SOURCE`，上传文件前不能运行。

## 变更内容

- 新增完整方案 `docs/architecture/0.0.3-system-design.md`，保留 `0.0.2` 作为历史方案。
- 修订快捷复制、数据源存储、运行物化、数据模型、API 和验收标准。
- 将版本号从 `0.0.2` 提升到 `0.0.3`。

## 变更边界

- 本次只修改方案文档和版本号，没有实现后端、前端或数据库代码。
- 没有修改 `features/` 原始功能素材。
- 平台仍不解析数据源业务内容。

## 验证

- 校验 `VERSION` 为 `0.0.3`。
- 校验 `0.0.3` 完整方案明确区分功能版本默认数据源和客户数据源版本。
- 校验复制规则明确“共享代码、不共享客户数据源、从包内默认文件初始化”。
- 校验运行记录固定客户数据源版本，Runner 按 `request_id` 创建独立文件路径。
