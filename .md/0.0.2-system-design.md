# 0.0.2 — 完整系统方案修订

## 日期

2026-09-08

## 变更目标

根据最新需求重新编写完整重构方案，收紧平台与业务脚本的边界，并把低运维成本作为交付约束。

## 变更内容

- 新增 `docs/architecture/0.0.2-system-design.md`。
- 明确删除平台“重新执行失败项”能力以及相关数据表、接口、SDK 和前端入口。
- 明确失败判断、失败项保存、网络重试和业务补偿均由脚本负责。
- 明确系统日常配置写入后台系统设置，不要求用户维护 `.env`。
- 设计首次启动自动生成实例密钥和一次性初始化码。
- 完整整理用户/客户多对多、客户功能、数据源文件、配置、运行子进程、实时日志、定时任务、快捷复制、安全、依赖管理、SQLite、备份恢复和 Docker 交付方案。
- 恢复导入记录中存在但工作区缺失的原始 `features/ozon.zip` 与 `features/shopify.zip`；不修改其内容。
- 将项目版本从 `0.0.1` 提升到 `0.0.2`。

## 变更边界

- 本次只新增设计与变更文档、恢复缺失的原始素材并更新版本号。
- 未开始重写后端或前端代码。
- 未修改 `features/` 内任何既有文件内容。
- `ozon_Inventory.zip` 仅作为需求样例保留，未改写其中业务脚本。

## 验证

- 校验 `VERSION` 为 `0.0.2`。
- 校验方案文档和变更文档存在且可读取。
- 校验 `features/ozon.zip` 与 `features/shopify.zip` 的 SHA-256 和上游暂存副本一致。
- 校验完整方案中不存在平台失败项重跑功能，并明确环境变量不是日常配置入口。
