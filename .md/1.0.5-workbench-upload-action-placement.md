# 1.0.5：工作台上传入口位置调整

## 1. 调整原因

`1.0.4` 将上传入口做成了功能列表中的独立卡片。实际期望不是新增一张卡，而是把操作放进已有功能卡片，与“配置管理”处于同一操作区。

本次只调整入口位置，不改变已经完成的弹窗上传、格式读取、客户选择、身份复验或后端校验。版本由 `1.0.4` 提升为 `1.0.5`，不重新制作桌面交付 ZIP。

## 2. 最终页面行为

- 移除工作台中的独立“上传功能包”卡片；
- 每张现有功能卡片的操作区增加“上传功能包”；
- “上传功能包”和“配置管理”相邻，均只向管理员显示；
- 点击后停留在工作台并直接打开原上传窗口；
- 单客户视图自动使用当前客户；
- 全部客户视图从某张卡片点击时，先带入该卡片明确展示的所属客户，同时允许管理员在窗口中搜索并改选；
- 当前范围没有任何功能时，在原空状态内保留“上传功能包”按钮，以免首次登记陷入没有入口的死路；
- 普通业务用户既看不到卡片内上传入口，也看不到空状态上传按钮。

## 3. 为什么不把上传绑定为强制更新当前功能

工作台按钮的位置属于操作入口调整，现有上传协议仍以包内 `__meta__.name` 决定它是新功能还是已有功能的新版本。平台不能因为用户从某张卡片点击，就在没有检查包内身份的情况下强行把另一份代码归到这张卡片。

上传已有功能的新版本后，平台仍不静默切换客户当前运行版本；管理员需要在功能管理中确认并切换。这条规则用于避免测试包上传后立即影响生产任务，本次不改变。

## 4. 保留的安全边界

- 管理员前端可见性和后端权限校验；
- 管理区网络门；
- CSRF；
- 敏感操作密码复验；
- 后台允许压缩格式；
- 包大小、条目、路径、压缩比和静态元数据校验；
- Web 不导入或执行上传代码；
- 上传成功后刷新工作台并显示右上角通知。
