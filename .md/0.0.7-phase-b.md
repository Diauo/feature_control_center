## 关键设计结论

1. 客户功能共享不可变代码版本，不共享配置和当前数据源。
2. 上传新代码版本不会静默替换客户当前版本或当前文件。
3. 平台保存文件但不理解 Excel、商品或库存字段。
4. 密钥密文绑定客户功能和配置键，不能跨记录调换。
5. 依赖环境按输入指纹复用，平台解释器永不被动态修改。
6. “内网”由实际 CIDR 定义，不把私网网段当成公司边界。
7. 管理区自锁恢复只在 Docker 主机侧提供，不开放公网后门。
8. 本阶段不实现失败商品、失败项重跑、业务网络重试或脚本执行。

## 已知阶段边界

依赖构建已经与数据库写事务分离，但阶段 B 暂时由管理员上传/重试请求同步等待。长时间依赖下载可能遇到外部代理请求超时；阶段 C 必须由持久 Runner 队列领取 `PREPARING` 环境，并让上传接口快速返回，不能用 Web 进程临时线程替代可靠队列。当前表结构、指纹、缓存和失败重试接口均可直接沿用。
