# 1.1.0 通用执行结果报表

日期：2026-09-11

## 变更原因

原有运行日志能完整记录过程，但运行记录无法直接回答“一共处理多少条、成功多少条、失败多少条”，业务人员还会直接看到脚本内部 `finalStatus` 枚举。直接解析日志或为 OZON 写固定映射会把业务规则塞进平台，也无法服务后续不同脚本。

本次在不改变商品、库存和失败重试边界的前提下，增加由功能脚本主动提交的通用结构化报表。平台只校验、保存、中文展示和导出，业务状态仍由脚本决定。

## 已完成

### 工作台

- 把“上传功能包”从具体功能卡片移到顶部“已登记功能”汇总卡片；
- 单客户范围自动选择当前客户；
- 全部客户范围要求在弹窗内明确选择目标客户；
- 功能管理原有上传和运行入口保持不变。

### 功能包契约

- `__meta__.report` 声明报表标题、对象名称和通用业务列；
- `ctx.report` 支持成功、失败、无数据、跳过和未完成五种结果；
- 正常返回自动提交完成标记；
- 限制列数、明细数、字符串和事件体积，并拒绝疑似密钥字段；
- 未适配报表的旧功能完全兼容。

### Runner 与存储

- 报表与实时日志复用已鉴别的子进程事件通道，但分别持久化；
- Runner 在终态前排空并保存最后一批报表指令；
- 新增 `run_report` 和 `run_report_item`，迁移版本为 `0009_run_reports`；
- 停止、超时、中断、异常、条数不一致或指令校验失败时封存为“未完整”；
- 报表明细跟随任务日志保留期清理，汇总数字长期保留。

### 页面与导出

- 运行记录新增“业务结果”，显示总数、成功数、失败数和必要补充计数；
- 运行详情新增最终报表汇总、状态筛选、服务端分页和动态明细列；
- 所有业务状态使用中文，日志上下文默认折叠为“技术字段”；
- 提供 XLSX 导出，包含执行汇总与结果明细，并防止公式注入；
- 报表下载逐任务校验客户权限并写审计。

### 示例与文档

- 起步模板、交付验收示例和实时日志稳定性测试已接入 `ctx.report`；
- 功能包开发规范、管理员手册、验收清单、版本兼容说明和架构说明已同步更新；
- 平台没有增加失败项重跑、商品查询或业务枚举映射。

## 兼容与升级

- 系统版本：`1.1.0`；
- 数据库迁移：`0009_run_reports`；
- 新依赖：`openpyxl==3.1.5`，用于服务端生成 Excel；
- 原有功能包、运行日志、数据源和配置不迁移、不重写；
- 从旧版升级时必须使用正式更新或整包部署流程，不能只替换部分 Python 文件。
