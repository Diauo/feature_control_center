# 0.0.8 阶段 C 改动记录

日期：2026-09-08  
主题：Runner、可停止子进程、运行快照与实时日志

## 需求对应

- Flask 只创建持久任务，不直接托管脚本进程；
- 独立 Runner 拉起、停止、超时和回收 Python 功能；
- 功能运行中可在前端实时查看 SDK/stdout/stderr/平台日志；
- 完成后从同一事件表下载 `.log` 或 `.jsonl` 最终日志；
- 功能版本、客户独立数据源和配置在排队时固化；
- 不增加失败商品、失败项重跑或任何商品业务模型；
- 依赖准备从上传请求迁出，由 Runner 持久消费 `PREPARING`；
- 运行参数进入后台设置，不增加 Docker 必填环境变量。

### 数据与安全

- 新增 Alembic `0003_phase_c`；
- 新增 `run`、`run_event`、`runner_heartbeat`；
- 新增活动任务部分唯一索引，数据库层阻止同一客户功能并行；

- 新增持久队列领取、全局并发和同功能串行；

- stdout/stderr 使用独立读取线程和有界单行读取；
- 日志按条数/时间批量写 SQLite；
- 依赖环境由 Runner 后台线程准备，不阻塞日志监督主循环。

- 为原类型注解导入提供运行目录内兼容模块；
- 不提供失败商品或业务重试抽象。

### Web 和前端

- 新增运行、停止、列表、详情、事件、SSE 与日志下载接口；
- 工作台“运行”按钮创建任务后立即进入日志页；
- 新增运行记录页和 Apple 风格暗色实时控制台；
- 支持 SSE 序号去重、自动重连、自动滚动和终态封存提示；
- 系统设置新增 Runner 和日志参数；
- 功能配置页新增最长运行时间覆盖项。

### 容器

- 新增同时监督 Web 和 Runner 的 `fcc-launcher`；
- Web 以 `fcc` 运行，功能进程以独立的 `fcc-script` 运行；
- Runner 不监听网络，子进程启动前清组、降权并设置 `no_new_privs`；
- Compose 只恢复启动器完成 SQLite 共享权限、降权和进程组终止所需的 capabilities；
- 不新增 Redis、消息队列或数据库服务。

## 根本设计理由

不能把进程句柄保存在 Flask 内存中：浏览器断开、代理超时或 Web 重启都会让平台失去停止能力。SQLite 任务记录是当前业务量下最小但可靠的持久边界。Web 与 Runner 分离后，任务的存在和停止意图不依赖 HTTP 生命周期。

不能在执行时读取客户功能的当前文件或当前配置：用户可能在排队和实际启动之间修改它们，导致日志无法回答“这次到底用了什么”。因此创建任务时固化不可变 ID 和加密配置快照。

不能在子进程退出时立即写终态：stdout/stderr 管道仍可能有缓冲内容。Runner 必须先等待读取线程结束并刷新日志，再写最终平台事件与终态。

生产前端产物已复制到 `backend/app/web/static/`。本机没有可用 Docker CLI，因此本轮无法实际构建和启动 Linux 镜像；Dockerfile、Compose、Linux UID/capability 和 TERM/KILL 路径已按交付配置完成，但仍需在有 Docker 的验收机做一次镜像级冒烟。

第一次整体验证暴露并修正了两个根因：新建依赖环境遗漏 `PREPARING` 赋值，以及没有 ORM relationship 时 `run_event` 可能先于父 `run` 刷新导致外键失败。最终实现先显式刷新父运行记录，再写首条事件；不是关闭外键或捕获后忽略。
