# 1.0.4：工作台上传功能卡片

## 1. 变更目标

工作台原来的“上传功能”位于页面标题右侧，点击后跳到功能管理。虽然没有破坏权限边界，但用户上传后还要返回工作台运行，操作链仍然被拆成两个页面。

本次把上传入口放进工作台功能卡片区域。管理员点击“上传功能包”卡片后，直接在当前页面完成目标客户和归档文件选择，不改变工作台路由，也不复制后端上传接口。

版本由 `1.0.3` 提升为 `1.0.4`。本次只更新源码和本地静态资源，不重新制作桌面交付 ZIP。

## 2. 页面行为

### 2.1 单客户范围

上传窗口自动带入左上角当前客户，并以只读字段显示。文件登记完成后关闭窗口、刷新当前工作台数据，并在右上角显示客户名和文件名。

### 2.2 全部客户范围

上传窗口不使用切换前保留在会话中的客户 ID。管理员必须在可搜索下拉框中重新选择一个启用客户，未选择前不能提交。这避免“页面显示全部客户、实际悄悄上传给上一个客户”的上下文错误。

### 2.3 空工作台

没有已登记功能时，管理员仍能看到上传卡片，并在相邻卡片中看到首次登记提示。普通用户不显示上传卡片，继续看到联系管理员的空状态。

## 3. 上传闭环

工作台上传继续复用原有后端接口：

```text
POST /api/admin/features/versions
```

安全链路没有降低：

- 仅管理员显示入口，后端仍独立校验管理员身份；
- 管理区网络门、CSRF 和上传限流规则不变；
- 需要近期身份验证时，上传窗口暂时关闭并显示独立密码复验窗口；
- 复验成功后恢复原客户和文件并继续上传；
- 功能包格式、大小、条目、路径、压缩比、元数据、依赖和默认数据源仍由后端校验；
- Web 请求不会导入或执行包内 Python 代码。

## 4. 共用代码

新增 `frontend/src/lib/featurePackages.ts`，集中维护格式到扩展名的映射和 multipart 上传请求。工作台与功能管理共同使用该模块，避免以后新增压缩格式时两个页面出现不同的 `accept` 列表或表单字段。

功能管理继续承担版本历史、依赖重试、版本切换和跨客户复制，不因工作台快捷上传而删除原入口。
