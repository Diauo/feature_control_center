# 0.0.9 改动记录：运行日志自动清理

日期：2026-09-08  
版本：`0.0.9`

## 需求

运行日志默认保留 180 天并自动删除，保留天数可以从后台配置，不增加环境变量或独立服务。

## 改动

- 新增 `logs.retention_days`，默认 180，范围 0～3650，0 表示关闭自动清理；
- Runner 启动后检查到期日志，之后按小时检查并以每批最多 200 个任务的短事务处理；
- 只删除达到保留期的终态任务事件，活动任务不参与清理；
- 保留运行摘要和最终状态，新增 `logs_purged_at` 明确记录日志清理时间；
- 已清理任务的文本和 JSONL 下载返回 `410 RUN_LOGS_PURGED`，不生成误导性的空日志；
- SSE 对已清理记录立即发送最终任务事件并关闭；
- 运行记录和详情页显示日志已清理，下载操作停用；
- 新增 Alembic `0004_log_retention` 和到期扫描索引；
- 更新 README、阶段 C 补充文档、容器标签和全部项目版本号。

## 设计理由

日志正文通常是 SQLite 增长最快的部分，但删除整个任务会丢失 request ID、客户归属、功能版本和最终状态。因此本次只删除 `run_event`，保留轻量任务摘要。清理由现有单实例 Runner 执行，避免 Web 请求承担长事务，也避免为一个低频维护动作引入 cron 或新服务。

不自动执行 `VACUUM`：删除页可以被 SQLite 复用，而在线全库重写可能明显增加锁等待并需要额外磁盘空间。物理压缩应作为停机维护操作。
