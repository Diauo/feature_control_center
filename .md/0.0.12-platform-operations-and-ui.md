# 0.0.12 平台运维、安全审计与界面体验改动记录

版本：`0.0.12`  
日期：`2026-09-09`

## 一、改动目标

本次更新不改变平台“只管理、调度和停止 Python 功能，不接管业务逻辑”的边界。改动集中解决以下日常问题：

1. 侧栏品牌和装饰信息占空间，客户下拉框、导航收起和配置入口不够顺手；
2. 系统管理员与业务用户混排，权限边界在界面上不够直观；
3. 原审计记录缺少角色、客户、请求和终端快照，账号或客户后续改名后难以还原当时事实；
4. 功能包只支持 ZIP，无法覆盖甲方常见的 Linux 归档交付方式；
5. 平台服务自身没有可在后台查看的状态、程序日志、版本和更新记录；
6. 系统时区依赖手写，容易输入错误，也无法对照浏览器和服务器检测结果。

## 二、界面与交互

### 2.1 导航与品牌

- 展开侧栏只显示数据库中的系统名称，不再显示字母图标、`Feature Control` 或底部阶段信息；
- 桌面侧栏可收起为 76px 图标栏，状态保存在浏览器本地；
- 收起状态使用 Lucide 线性图标，鼠标悬停由 Reka UI Tooltip 显示文字；
- 展开状态仍保持纯文字导航，避免图标和文字同时出现造成视觉噪音；
- 移动端抽屉始终恢复完整文字导航，避免桌面收起状态影响手机操作；
- 登录页取消字母品牌图标，改为纯文字系统名称。

### 2.2 客户和时区选择

- 新增通用 `SearchCombobox`，由 Reka UI 提供键盘导航、弹层和可访问性基础；
- 左上角客户切换改为可搜索下拉框；
- 系统设置时区改为可搜索 IANA 时区下拉框；
- 页面同时标注浏览器时区和服务器检测时区，但不会未经管理员确认覆盖数据库中的现有时区；
- 首次初始化也会把浏览器选择的时区写入数据库。

### 2.3 工作台配置

- 工作台的“配置管理”不再跳转到功能管理路由；
- 点击后在当前工作台打开右侧配置抽屉；
- 配置密钥仍只显示是否已设置，保存仍要求近期密码复验和管理区网络校验；
- 旧配置 URL 保留兼容重定向，已有书签不会直接失效。

### 2.4 用户管理

- 业务用户和系统管理员改为两个独立页签；
- 新建入口随当前页签固定账号类型，不再在一个表单中混合选择角色；
- 只有业务用户显示客户多选和客户范围；
- 系统管理员仍由后端最后管理员保护、自操作保护和近期密码复验兜底。

### 2.5 文案收敛

- 移除登录后业务页面中的英文眉题；
- 工作台移除无上下文的 `v1` 徽标；
- 需要表达版本时统一使用“代码版本 N”，避免和平台版本混淆。

## 三、功能包格式

### 3.1 支持范围

系统支持并可在后台逐项启用：

- ZIP：`.zip`
- 7z：`.7z`
- TAR：`.tar`
- TAR + Gzip：`.tar.gz`、`.tgz`
- TAR + Bzip2：`.tar.bz2`、`.tbz2`
- TAR + XZ：`.tar.xz`、`.txz`

RAR 不支持。原因不是界面成本，而是交付包需要额外的 RAR 解码链路、许可证和攻击面，和当前“单 Docker、少服务、低维护”目标不匹配。

### 3.2 统一安全约束

所有格式进入同一条静态检查管线：

- 扩展名必须对应系统启用的格式，内容还必须能被相应解析器正确读取；
- 禁止绝对路径、父目录跳转、Windows 盘符、反斜杠路径、NUL 和 Unicode 规范化歧义；
- 禁止符号链接、硬链接、设备文件、FIFO 和加密归档；
- 限制归档大小、条目数、单文件大小、解压总量和压缩比；
- 拒绝大小写冲突路径；
- 仍只通过 AST 读取根目录 `__init__.py` 的字面量元数据，不 import 上传代码；
- Runner 执行前再次校验包 SHA-256，并通过同一安全路径规则物化文件。

7z 由固定版本 `py7zr==1.1.3` 解析；ZIP 和 TAR 系列使用 Python 标准库。

## 四、安全审计

数据库迁移新增不可变审计快照字段：

- 操作人角色、用户名、显示名；
- 客户 ID、客户名称；
- 对象类型、对象 ID、对象名称；
- 请求方法、规范路由、请求 ID；
- 可信代理解析后的客户端 IP；
- 清理控制字符后的 User-Agent；
- 操作编码、结果、时间和经过筛选的 JSON 详情。

审计写入时立即固化这些值。用户、客户或功能后续改名、停用或删除，不会改变历史事实。旧记录不伪造角色快照，在界面中明确显示为旧数据。

新增或强化的敏感读取审计包括：

- 查看客户功能配置；
- 查看系统设置；
- 下载客户数据源；
- 下载版本默认数据源；
- 下载任务日志；
- 下载平台程序日志。

审计页面按“管理员操作、普通用户操作、登录与系统、全部”分区，并支持操作编码、结果、IP 和日期范围筛选。详情展开后展示完整请求、客户、对象和终端上下文。密码、会话令牌、配置密钥明文仍不会写入审计。

## 五、平台程序日志

### 5.1 写入

Web、Runner、Scheduler、Launcher 分别写入：

```text
data/system-logs/<service>/YYYY-MM-DD.jsonl
```

每行是一个 UTF-8 JSON 对象，包含 UTC 时间、服务、级别、logger 和消息。异常堆栈有独立字段。写入前清理控制字符并对常见 password、token、authorization、cookie、api key、secret 形态做脱敏。

Docker 启动器为四个目录设置共享组权限，因此 Web 可以只读展示其他进程日志，功能脚本账户仍无法访问平台数据目录。

### 5.2 保留策略

- 默认保留 `180` 天；
- 保留天数在系统设置单独配置；
- 可选总容量上限用 MiB 配置，数据库中保存字节数；
- `0` 表示不启用容量上限；
- 当天正在写入的文件绝不会被容量策略删除；
- 清理失败只记录错误并延迟重试，不中断 Runner 的进程监管。

任务运行日志继续保存在 SQLite，两类日志互不混用、互不覆盖。

### 5.3 后台查看

系统设置新增四个页签：

1. 运行状态：平台版本、活动任务、系统时区和 Web / Runner / Scheduler 心跳；
2. 系统参数：保留原有全部配置，并加入格式和程序日志设置；
3. 程序日志：按服务、UTC 日期和级别查看，页面可见时读取增量；
4. 更新记录：读取随交付包发布的结构化版本记录。

日志 API 只接受固定服务名和严格日期，不接受任意文件路径。下载动作会写入安全审计。

## 六、数据库与兼容性

- 新迁移：`0006_platform_operations`；
- 只为 `audit_log` 增加可空快照字段和索引，不重写旧审计记录；
- 新系统设置由实例启动时幂等补齐，已有 SQLite 文件可直接升级；
- 已保存的 ZIP 功能版本继续可运行；
- 后续在设置中停用某种格式只阻止新的上传，不会让已登记版本无法物化；
- 原项目 `features/` 未修改。
