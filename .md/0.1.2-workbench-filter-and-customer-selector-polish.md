# 0.1.2：工作台筛选与客户选择器细节

## 1. 目标

本次只处理四项已确认的界面细节，不改动功能调度、权限、数据源、更新系统或数据库结构：

1. 去掉顶部客户选择器搜索框的浅蓝色焦点圈；
2. 工作台结果总数不超过 20 条时不显示分页；
3. 工作台的搜索和状态筛选只在“全部客户”范围显示，单客户范围不显示筛选条。
4. 客户管理、用户管理和功能管理同样只在结果总数大于 20 条时显示分页。

版本由 `0.1.1` 提升至 `0.1.2`。

## 2. 设计决定

### 2.1 客户选择器焦点

不直接取消键盘焦点反馈。客户选择器的触发器和浮层搜索框改用中性灰边框与极浅阴影，既去掉突兀的品牌蓝色，又让键盘用户仍能判断当前焦点位置。修改仅作用于 `app-combobox`，不会改变登录、表单和危险操作的全局焦点规范。

### 2.2 列表分页

工作台、客户管理、用户管理和功能管理的默认页容量都是 20。每个列表均以当前查询返回的 `pagination.total` 为依据：总结果 `<= 20` 时只有一页，分页控件不产生有效价值，因此直接隐藏；总结果 `> 20` 时仍显示页码以及 20、50、100 的每页数量选择。筛选后的总数也遵守同一规则，后端服务端分页协议保持不变。

### 2.3 筛选作用域

“客户名称或功能名称”和状态筛选统一作为跨客户结果集的定位工具，只在“全部客户”范围显示。单客户范围直接展示该客户已登记的全部功能，不显示整个筛选条。

进入单客户范围时会同时清空搜索和状态值；请求层也只允许“全部客户”范围携带 `search` 与 `status` 参数，避免已经隐藏的旧条件继续影响数据。实现只调整工作台筛选条的显示和请求边界，没有重构页面结构。

## 3. 数据与兼容性

- 不新增或修改数据库表，无 Alembic 迁移；
- 不改变任何 API 响应结构；
- 不改变客户授权、功能运行和文件入参规则；
- 已有登录状态、配置、日志、任务和更新记录不受影响。
