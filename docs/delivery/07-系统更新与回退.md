# 系统更新与回退

## 1. 更新包是什么

系统更新使用 `.fcup` 签名包。它不是把源代码 ZIP 解压到正在运行的目录，而是把新版本及全部 Python wheel 放入持久卷，由稳定 Launcher 完成停服、备份、迁移、预检、切换和失败回退。

管理员入口位于“系统设置 → 系统更新”。更新记录、原包、状态和回退材料都保存在 `data/`，重建容器不会抹掉。

## 2. 安装前条件

- 当前完整备份已复制到异机；
- 没有排队、启动、运行或停止中的任务；
- 已核对目标版本、当前版本、Linux 架构和 Python 版本；
- 更新包来自正式发布渠道，SHA-256 与发布记录一致；
- 已阅读数据库迁移和回退兼容说明；
- 有人在更新窗口观察系统状态和业务抽查。

系统会再次校验 Ed25519 签名、清单、每个 wheel、大小、路径、压缩比、兼容范围、Python 3.14 和目标架构。浏览器断开不会取消正在执行的更新。

## 3. 安装过程

1. 管理员选择 `.fcup`；
2. 输入当前管理员密码重新认证；
3. Web 保存并登记请求；
4. Launcher 停止 Web、Runner、Scheduler；
5. 在新的版本目录离线安装 wheel，不访问 PyPI；
6. 使用 SQLite Online Backup API 备份并检查数据库；
7. 运行迁移和候选版本预检；
8. 启动候选服务，等待 Web 就绪与 Runner/Scheduler 新鲜心跳；
9. 原子切换当前版本指针；
10. 任一步失败时恢复更新前数据库和程序版本。

不要刷新页面后重复上传同一个包。更新状态已持久化，重新进入页面即可继续查看。对于明确失败且保留原签名包的记录，使用页面提供的重试，不要手工复制更新目录。

## 4. 两种回退

**安装失败自动回退**：候选版本未正式接管，系统恢复迁移前数据库和原程序。

**管理员主动回退**：只在更新清单声明向后兼容时提供。它切回上一程序版本，但保留更新后新增的业务数据。若数据库结构不能被旧版安全读取，发布人员不得把更新标记为可回退。

主动回退前仍应创建整包备份。不要用旧数据库覆盖更新后产生的运行记录和配置，除非是在灾难恢复决策下明确接受数据丢失。

## 5. 更新签名密钥

仓库和客户服务器只保存 Ed25519 公钥。私钥必须放在开发方离线受控目录，不能进入：

- Git 仓库；
- Docker 镜像；
- 客户服务器；
- 交付 ZIP；
- `.fcup` 包；
- 聊天工具和普通网盘。

首次建立信任链：

```bash
fcc-update-package generate-key \
  --private-key /secure/offline/update-signing-private.pem \
  --public-key backend/app/update_public_key.pem
```

更换公钥、Launcher、Python、SQLite/系统库或 7-Zip 属于基础镜像升级，不能依赖当前公钥边界内的 FCUP 自我替换，应制作新的完整交付包并按迁移流程更换。

## 6. 制作 FCUP

在与生产相同架构和 Python 3.14 的隔离 Linux 构建机完成：

```bash
cd frontend
npm ci
npm run build
cd ..
rm -rf backend/app/web/static
cp -R frontend/dist backend/app/web/static

python3.14 -m build --wheel backend
mkdir -p wheelhouse
python3.14 -m pip download \
  --only-binary=:all: \
  --dest wheelhouse \
  backend/dist/feature_control_center-2.4.1-py3-none-any.whl

fcc-update-package build \
  --wheelhouse wheelhouse \
  --private-key /secure/offline/update-signing-private.pem \
  --output feature-control-center-2.4.1-linux-x86_64.fcup \
  --version 2.4.1 \
  --compatible-from '>=2.4.0,<3.0.0' \
  --platform linux_x86_64 \
  --python-version 3.14 \
  --database-revision 0012_feature_deletion \
  --notes-file release-notes.txt \
  --rollback-compatible
```

只有数据库和数据格式确定向后兼容时，才加 `--rollback-compatible`。`wheelhouse` 必须包含应用及全部间接依赖 wheel，并且只能包含一个目标版本的应用 wheel。

## 7. 发布演练

正式上传前，在从生产备份恢复出的隔离副本完成：

1. 当前版启动；
2. 上传并安装更新；
3. 登录、客户切换、配置读取、数据源下载；
4. 运行交付验收功能；
5. 重启容器后复查；
6. 若声明可回退，执行主动回退并重复验收；
7. 记录更新包 SHA-256、耗时和结果。

没有演练证据的 FCUP 不进入生产。
