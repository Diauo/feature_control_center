# 功能包开发规范

## 1. 平台契约

功能包是一个常见压缩文件。根目录必须直接包含 `__init__.py`，不能再套同名文件夹。系统默认支持 ZIP、7z、TAR、TAR.GZ、TAR.BZ2、TAR.XZ 和 RAR；管理员可在系统设置关闭不需要的格式。RAR 依赖容器内 7-Zip，只接受无密码包。

推荐目录：

```text
my_feature.zip
├── __init__.py
├── requirements.txt       # 可选
├── dataSource.xlsx        # 可选默认数据源
├── client.py              # 可选业务模块
└── wheels/                # 可选离线依赖 wheel
```

平台拒绝绝对路径、`..`、软硬链接、设备文件、重复路径、加密包和异常压缩比。不要把凭据、`.env`、浏览器 Cookie 或客户生产数据放进源码包。

## 2. 元数据

`__meta__` 必须是 Python 字面量字典，而且在 `__init__.py` 中只声明一次。静态检查不会执行元数据代码。

```python
__meta__ = {
    "name": "库存同步",
    "description": "从业务系统同步到目标店铺",
    "entrypoint": "run",
    "configs": {
        "endpoint": {
            "type": "string",
            "label": "接口地址",
            "description": "完整 HTTPS 地址",
            "required": True,
        },
        "api_token": {
            "type": "secret",
            "label": "接口密钥",
            "required": True,
        },
        "page_size": {
            "type": "integer",
            "label": "分页大小",
            "required": True,
            "default": 100,
            "min": 1,
            "max": 1000,
        },
        "mode": {
            "type": "enum",
            "label": "模式",
            "required": True,
            "default": "normal",
            "options": ["normal", "dry-run"],
        },
    },
    "data_source": {
        "filename": "dataSource.xlsx",
        "required": True,
        "extensions": [".xlsx"],
        "description": "商品和店铺控制表",
    },
    "report": {
        "title": "库存同步结果",
        "item_label": "商品",
        "columns": [
            {"key": "sku", "label": "商品编码", "type": "string"},
            {"key": "storeCode", "label": "店铺编码", "type": "string"},
            {"key": "quantity", "label": "库存", "type": "integer"},
        ],
    },
}
```

配置类型：

| 类型 | Python 值 | 说明 |
| --- | --- | --- |
| `string` | `str` | 单行文本 |
| `text` | `str` | 多行文本 |
| `integer` | `int` | 整数，可设 `min`/`max` |
| `number` | `int`/`float` | 有限数字，可设 `min`/`max` |
| `boolean` | `bool` | 开关 |
| `enum` | 声明的标量 | 必须提供 `options` |
| `secret` | `str` | 密钥，不允许非空默认值 |

旧式 `(默认值, 说明)` 仍可兼容，但新功能不得继续使用。元数据中的 `customer` 会被忽略，客户归属由上传操作决定。

## 3. 入口函数与上下文

新功能使用一个参数：

```python
def run(ctx) -> None:
    endpoint = ctx.config.get("endpoint")
    token = ctx.config.get_secret("api_token")
    source = ctx.get_data_source_path()
    ctx.log.info("任务开始", requestId=ctx.request_id)
```

兼容入口 `run(configs, ctx)` 仍可执行，但 `configs` 会包含密钥，开发人员更容易误打日志。新代码应通过 `ctx.config.get_secret()` 单独取密钥。

上下文稳定接口：

| 接口 | 用途 |
| --- | --- |
| `ctx.request_id` | 本次运行唯一编号 |
| `ctx.customer_id` | 客户编号 |
| `ctx.feature_id` | 客户功能编号 |
| `ctx.config.get(key, default)` | 读取非密钥配置 |
| `ctx.config.get_secret(key)` | 读取已声明的密钥 |
| `ctx.get_data_source_path()` | 本次冻结的数据源文件路径或 `None` |
| `ctx.raise_if_cancelled()` | 响应停止请求 |
| `ctx.log.debug/info/warning/error()` | 写结构化实时日志 |
| `ctx.debug/info/warning/error()` | 兼容日志快捷方法 |
| `ctx.report` | 提交本次执行的通用汇总和逐条结果 |

## 4. 数据源

平台只管理一个通用文件，不解析内容。脚本必须通过 `ctx.get_data_source_path()` 取得本次执行快照：

```python
from pathlib import Path

def run(ctx):
    source: Path | None = ctx.get_data_source_path()
    if source is None:
        raise RuntimeError("缺少数据源")
    content = source.read_bytes()
```

不要通过数据库、固定宿主机路径或客户名称拼接路径。功能复制后，不同客户引用相同代码版本，但各自拥有独立数据源修订；运行时路径由平台正确物化。

如果包内携带声明文件，它会成为新客户的默认副本。用户在页面替换后，下载和后续运行使用该客户当前修订，不会修改功能包或其他客户。

## 5. 执行结果报表

报表是功能包与平台之间的通用结果契约。平台不知道什么是商品、订单或库存，也不会从日志文本、业务 JSON 或异常内容中猜测成功和失败。功能包在 `__meta__.report` 声明要展示的业务字段，在处理完成后通过 `ctx.report` 明确提交结论。

`report.columns` 支持 1 到 30 个字段，字段类型为 `string`、`integer`、`number` 或 `boolean`。整数必须位于 JavaScript 可精确表示的安全整数范围内，数字必须是有限值。字段只应包含业务识别和核对信息，不得包含 Token、密码、Cookie 等密钥。一次运行默认最多提交 60000 条明细，管理员可在“系统设置 → 系统参数 → Runner 与任务日志”中调整。任务启动时会固化当次上限，因此运行途中修改不会改变正在执行的任务。

标准状态：

| SDK 方法 | 页面和 Excel 显示 | 使用场景 |
| --- | --- | --- |
| `ctx.report.success(...)` | 成功 | 该项业务已经按脚本规则完成 |
| `ctx.report.failed(...)` | 失败 | 该项已经判定失败，`reason` 必须说明原因 |
| `ctx.report.no_data(...)` | 无数据 | 上游没有可同步内容，属于正常结论 |
| `ctx.report.skipped(...)` | 已跳过 | 脚本按业务规则主动跳过 |
| `ctx.report.unfinished(...)` | 未完成 | 已识别该项，但本次没有形成最终业务结论 |

完整示例：

```python
def run(ctx) -> None:
    rows = load_rows(ctx.get_data_source_path())
    ctx.report.start(expected_total=len(rows))

    for row in rows:
        ctx.raise_if_cancelled()
        values = {
            "sku": str(row.sku),
            "storeCode": str(row.store_code),
            "quantity": int(row.quantity),
        }
        try:
            result = sync_one(row)
        except TimeoutError:
            ctx.log.error("目标接口超时", sku=row.sku, storeCode=row.store_code)
            ctx.report.failed(values=values, reason="目标接口超时", reason_code="NETWORK.TIMEOUT")
            continue

        if result.is_empty:
            ctx.report.no_data(values=values, reason="上游没有库存记录")
        else:
            ctx.report.success(values=values, reason="库存已同步")
```

`expected_total` 是脚本已经识别出的预计处理总数。声明后，明细条数必须与它一致；少报或多报都会让本次报表标为“未完整”。入口函数正常返回时 SDK 自动提交完成标记，无需在每个返回分支重复调用 `complete()`。任务被停止、超时、Runner 中断、脚本异常、明细数量不一致或存在非法报表指令时，平台保留已经收到的明细，并把报表明确标为“未完整”，不会把缺失项伪装成失败项。

运行记录显示总数、成功数和失败数；详情页提供中文状态、逐条原因和业务字段。终态报表可下载为 Excel，内含“执行汇总”和“结果明细”两个工作表。为避免表格公式注入，导出时会把以 `= + - @` 开头的文本按普通文字写入。

报表不是失败项重试系统。失败如何判定、是否重试以及重试多少次仍由脚本负责。旧功能包不声明 `report` 也能继续运行，只是页面提示“未提交报表”。日志和报表各司其职：日志记录过程，报表提供业务结论；不能只提交报表而省略关键执行日志。

## 6. 日志闭环

一次执行应至少记录：

1. 开始、请求范围和不敏感参数；
2. 数据源读取结果和有效记录数；
3. 每个业务对象的唯一识别信息；
4. 成功、失败、无数据、跳过的明确结论；
5. 外部接口失败的系统、阶段、状态码和可追踪编号；
6. 最终总数和任务结论。

示例：

```python
ctx.log.info("商品同步成功", sku=sku, storeCode=store_code, quantity=quantity)
ctx.log.warning("源系统无数据，已跳过", sku=sku, storeCode=store_code)
ctx.log.error("目标接口拒绝请求", sku=sku, statusCode=response.status_code)
```

禁止记录密码、Token、完整请求头、Cookie、身份证号等敏感信息。不要只写“失败了”；日志应让业务人员能依据 `requestId + SKU` 反查发生在哪一步。

最终日志由平台封存并提供下载。平台不会自动重跑失败项；失败处理属于业务脚本。业务人员日常核对优先查看最终报表，开发人员排障再查看实时日志和技术字段。

## 7. 停止与超时

Runner 将每次功能放在独立进程中。脚本必须在可控边界检查停止：

```python
for item in items:
    ctx.raise_if_cancelled()
    process_one(item)
```

网络请求必须设置连接和读取超时，长等待应拆成短段并检查取消。功能包不得自行创建子进程、守护进程或后台线程。即使脚本没有合作，平台也会在宽限期后结束进程，但当次业务调用可能无法优雅收尾。

## 8. 第三方依赖

`requirements.txt` 每行一个标准 Python requirement，不允许 pip 参数或行尾选项。交付标准要求使用精确版本：

```text
requests==2.34.2
openpyxl==3.1.5
```

不要写 `pip install`、不要在脚本启动时安装包、不要修改平台 Python 环境。系统按规范化 requirements 的哈希复用隔离环境，多个客户复制同一功能不需要重复安装。

在线方式：只放 `requirements.txt`，Runner 首次准备时从配置的软件源下载。

离线方式：把与服务器 Linux 架构、Python 3.14 和依赖闭包完全匹配的 wheel 放入 `wheels/`。离线包仍保留 `requirements.txt`。不得把 Windows wheel 放入 Linux 功能包。

示例下载命令（在 Linux x86_64、Python 3.14 构建机执行）：

```bash
python3.14 -m pip download \
  --only-binary=:all: \
  --dest wheels \
  -r requirements.txt
```

若任一依赖没有兼容 wheel，优先更换到有正式 wheel 的版本，不要在生产服务器临时安装编译器。

## 9. 发布前自检

- `__init__.py` 位于压缩包根目录；
- `__meta__` 只有字面量且配置字段完整；
- 密钥全部为 `secret`，没有默认值；
- 默认数据源文件名与声明一致；
- 所有外部请求有超时并校验证书；
- 循环调用 `ctx.raise_if_cancelled()`；
- 每个业务对象有闭环日志；
- 声明报表时，每个识别到的业务对象都提交且只提交一条最终状态；
- 报表字段不包含密钥，失败、跳过和未完成项有可读原因；
- requirements 精确锁定并在目标 Python 上验证；
- 不创建子进程，不写固定主机路径；
- 测试客户先跑通，再复制到生产客户；
- 变更业务逻辑时上传新功能版本，不覆盖旧包。

完整可编辑代码见 `examples/feature-packages/starter_template/`。
