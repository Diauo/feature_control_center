# 版本与兼容性

## 1. 当前基线

| 项目 | 基线 |
| --- | --- |
| 系统版本 | 2.4.0 |
| 部署方式 | Linux 单机 Docker Compose |
| 容器 Python | 3.14.4 |
| 前端构建 Node | 22.22.0 |
| 数据库 | SQLite，容器内编译版本不低于 3.51.3 |
| 功能包 Python | 与容器 Python 3.14 ABI 一致 |
| 更新包 | Ed25519 签名 FCUP |
| 数据库迁移版本 | `0012_feature_deletion` |

## 2. 版本规则

系统使用 `主版本.次版本.修订版本`：

- 修订版本：兼容修复，不改变公开功能包契约；
- 次版本：增加兼容功能或管理能力，可能包含数据库迁移；
- 主版本：存在需要迁移评审的契约、运行环境或部署边界变更。

每次发布必须同步更新 `VERSION`、Python 包版本、前端包版本、Docker 镜像标签、OCI 标签、更新记录、文档示例和测试断言。

## 3. 功能包兼容

2.4.0 支持：

- `run(ctx)`；
- 兼容 `run(configs, ctx)`；
- 兼容旧的 `app.util.feature_execution_context.FeatureExecutionContext` 导入；
- 兼容 `ctx.log(message, level)`；
- 兼容 `ctx.error(message)` 等日志快捷方法；
- 新包可用 `__meta__.report` 与 `ctx.report` 提交通用执行结果；不声明报表的旧包继续运行；
- 单次报表明细默认上限为 60000，可在系统设置中调整；一次运行启动后沿用启动时的上限快照；
- 旧元数据二元组会转换并给出提示；
- 包内 `dataSource.*` 可推断，但新包必须显式声明。

兼容不代表旧业务依赖可在 Python 3.14 安装。旧包仍需检查第三方 wheel。

## 4. 架构边界

Dockerfile支持 `linux/amd64` 和 `linux/arm64`。离线 Docker 镜像和带二进制 wheel 的功能包都与架构绑定：

- amd64 镜像不能作为 arm64 原生交付物；
- `linux-amd64-offline` OZON 包不能上传到 arm64 生产环境；
- online 功能包可在目标服务器重新解析适合其架构的依赖，但前提是软件源提供兼容 wheel。

## 5. 升级约束

- FCUP 只允许升级到更高版本；
- 目标清单必须明确包含当前版本；
- Python 小版本、目标 Linux 架构和 Launcher 协议必须一致；
- 更新包只能更换 Python 应用 wheel，不能替换基础镜像中的 Python、SQLite、7-Zip、公钥或 Launcher 信任边界；
- 数据库迁移不可逆时，不能声明保留数据主动回退；
- 跨主版本必须先在生产备份副本演练。

## 6. 支持期限

本交付包未约定自动的软件支持期限。甲乙双方应在合同或运维交接中明确：缺陷响应、依赖安全升级、OZON/ME3 API 变更、证书和域名维护、Linux/Docker 补丁、备份巡检与恢复演练的责任人和周期。
