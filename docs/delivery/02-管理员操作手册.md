# 管理员操作手册

## 1. 首次初始化

部署终端会显示 `/setup` 地址和一次性验证码。打开该地址后设置首位系统管理员。管理员密码建议使用密码管理器生成，不与服务器、邮箱或其他系统共用。

初始化完成后，一次性验证码失效，`first-run.txt` 会失去用途。任何人要求通过聊天工具发送管理员密码或客户密钥，都应拒绝。

## 2. 先建立客户，再建立业务用户

推荐顺序：

1. 在客户管理中建立客户，名称使用甲方约定的正式简称；
2. 在用户管理中建立业务用户；
3. 为用户勾选其负责的客户；
4. 为用户勾选菜单权限（工作台、运行记录、定时任务、功能管理、用户管理、客户管理、安全审计；系统设置为管理员专属）；
5. 用业务账号登录，确认只能看到已授权菜单，且左上角只能选择获授权客户；
6. 系统管理员只用于后台管理，不与普通用户列表混用。

用户与客户是多对多关系。给用户解除某个客户后，该用户不应再看到该客户的功能、配置、日志和定时任务。菜单授权同样即时生效：调整后该用户的下一次请求立刻按新授权执行，无需重新登录；新建业务员默认授权「工作台 + 运行记录」，只授权「工作台」的账号只能执行功能和替换数据源。不要通过共享账号实现多人操作，审计记录需要对应真实操作人。

## 3. 注册功能

日常登记请在功能管理中完成：进入功能管理后，在“登记新版本”面板选择功能包并上传。工作台不再提供上传入口，只负责执行功能和替换数据源。当前为单个客户时会自动带入该客户；在“全部客户”视图打开时，必须先选择一个具体客户。平台会：

1. 校验压缩包格式、路径、大小和解压比例；
2. 静态读取根目录 `__init__.py` 的 `__meta__`；
3. 登记不可变功能版本和包内默认数据源；
4. 根据 `requirements.txt` 准备隔离依赖环境；
5. 依赖准备成功后把版本标为可用。

依赖环境准备期间不要反复上传相同包。失败时先看失败原因；修复包或网络后，使用准备重试。详细开发规则见 `03-功能包开发规范.md`。

## 4. 客户配置

在左上角选择客户后，从功能管理页对应功能的卡片打开“配置管理”。每个客户独立保存配置：

- 普通配置可查看和覆盖；
- `secret` 配置只允许重新填写或清除，页面和接口不返回明文；
- 保存前核对当前客户，避免把店铺凭据填到错误客户；
- 生产密钥不要写进功能包默认值、源码、日志或数据源。

配置管理可设置额外网络访问门。首次上线不要在代理地址尚未确认时贸然开启，否则可能把管理员自己锁在外面。误锁恢复见 `06-公网安全部署.md`。

## 5. 客户数据源

数据源是“客户 + 功能”维度的一份当前文件：

- 下载：取得该客户当前生效文件；
- 替换：上传新文件并形成新修订；
- 执行：任务创建时冻结当前修订，运行中再次替换不会改变已创建任务；
- 复制功能：代码版本保持引用不变，目标客户从该版本的默认数据源建立自己的独立副本；
- 后续修改：A 客户和 B 客户互不影响。

平台不解析 XLSX、CSV 或其他业务内容，只检查声明的扩展名和安全限制。表头、字段和业务规则由功能包负责。

## 6. 手工运行与实时日志

在工作台点击运行后进入本次请求（账号未开通「运行记录」菜单时只提示“任务已提交”、不会跳转，开通后即可查看运行记录）。每次执行都有唯一 `requestId`，并冻结：

- 客户与功能；
- 功能版本；
- 当时的配置快照；
- 当时的数据源修订；
- 手工、定时等触发来源。

浏览器通过实时事件流显示日志。页面断开不会停止任务；重新打开运行详情会从数据库续读。功能包如果声明并提交结构化报表，任务结束后详情页会自动切到“最终报表”：

- 汇总区显示总数、成功、失败、无数据、已跳过和未完成数量；
- 明细区按功能包声明的业务字段展示每条结果，状态和原因均使用中文；
- “导出 XLSX”下载完整最终报表，包含“执行汇总”和“结果明细”两个工作表，不受当前页面筛选和分页影响；
- 停止、超时、中断、脚本异常或预计总数与明细数不一致时，报表明确显示“未完整”，已有明细不会被改写；
- 未适配报表的旧功能继续正常运行，页面仍可查看和下载原始日志。

报表结论由功能脚本提交。平台不解析任意日志 JSON，不会把某个项目专用的 `finalStatus` 枚举硬编码为通用规则，也不会重跑失败项。功能开发人员应按 `03-功能包开发规范.md` 适配 `ctx.report`。业务人员日常核对使用最终报表，排查接口调用过程时再查看实时日志和折叠的技术字段。

点击停止后，平台先向脚本发送停止请求；脚本应在循环和耗时步骤之间检查取消状态。宽限期后仍未退出，Runner 会结束脚本进程并记录停止原因。脚本不得自行创建子进程。

## 7. 定时任务

定时任务同样属于客户和功能。启用前检查：

- 客户配置完整；
- 数据源是准备执行的版本；
- 功能版本状态可用；
- 系统时区正确；
- 并发策略符合业务要求；
- 已先手工成功运行一次。

修改时区会改变后续触发的解释方式。涉及跨国客户时，应把业务时区写入交接记录，不凭浏览器所在地猜测。

## 8. 功能快捷复制

复制面向“其他客户”，不是其他用户。复制时复用不可变代码版本，并为每个目标客户建立独立的：

- 功能启用记录；
- 配置值和密钥（按页面选择）；
- 默认数据源副本；
- 调度、日志和后续修订空间。

复制完成后必须切换到目标客户逐项复核密钥、仓库号和数据源。默认数据源只是起点，不代表目标客户业务数据已经正确。

## 9. 日志和审计

- 运行日志：业务脚本输出，按请求查看和下载；
- 执行报表：脚本提交的逐条业务结论，可在线核对和下载 Excel；
- 程序日志：Web、Runner、Scheduler、Launcher 的运行记录；
- 安全审计：登录、管理、配置、运行、更新等操作，包含时间、账号、角色、客户范围、IP、User-Agent、请求和目标快照；
- 普通用户操作与管理员操作分栏查看；
- 默认任务日志和程序日志均保留 180 天，可在系统设置分别修改。

缩短任务日志保留时间会在清理周期后同时删除过期的日志事件和报表明细；任务状态与报表汇总数字继续保留。正式变更前先确认法规、合同和业务追溯期限。

## 10. 账号离职与异常处置

业务人员离职时应立即禁用其账号并解除客户关系，不要删除或篡改历史审计。怀疑账号泄露时：

1. 禁用账号；
2. 重置相关客户密钥；
3. 检查安全审计和运行记录；
4. 备份现状；
5. 由安全人员检查反向代理和服务器登录记录。
