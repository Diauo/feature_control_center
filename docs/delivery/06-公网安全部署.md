# 公网安全部署

## 1. 基本原则

系统需要部署到公网，但配置区保存店铺和接口密钥。安全目标不是增加用户操作，而是把高风险控制放在服务器、反向代理、会话和审计层。业务人员仍只需要登录、选客户和点击运行。

## 2. 网络拓扑

推荐：

```text
互联网
  │ HTTPS 443
现有 WAF / Nginx / Caddy
  │ 仅代理节点可达
功能控制中心 127.0.0.1:8080
```

不要把 8080 直接对全网开放。宿主机只开放 SSH 管理来源和 HTTPS，数据库不监听网络端口。

## 3. HTTPS 与代理头

TLS 证书应由公司现有网关或受控 ACME 流程维护。代理必须：

- 强制 HTTP 跳转 HTTPS；
- 限制请求体大小，与系统上传上限一致；
- 支持实时日志的长连接并关闭不合适的响应缓冲；
- 传递 Host、X-Forwarded-Proto 和真实客户端 IP；
- 不覆盖或伪造来自公网的转发头；
- 对登录和上传做适度速率限制。

只有代理节点地址写入“可信代理 CIDR”后，系统才应信任其转发的客户端 IP。不要把 `0.0.0.0/0` 或 `::/0` 设为可信代理。

## 4. 登录会话

系统使用服务端会话 Cookie，不使用前端长期保存 JWT。浏览器只持有随机会话标识；会话状态、撤销和权限都在服务器端。安全属性包括 HttpOnly、SameSite、CSRF 校验、登录限流、密码哈希和会话过期。

HTTPS 上线后检查 Cookie 的 Secure 属性。管理员与业务用户使用个人账号，禁止共享管理员密码。离职或异常账号应立即禁用。

## 5. 配置管理额外访问门

配置管理支持：

- `ACCOUNT_ONLY`：通过账号权限即可进入；
- `TRUSTED_NETWORKS`：除账号权限外，客户端 IP 还必须命中配置的可信 CIDR。

“内网”不是写死 RFC1918 网段。系统根据管理员配置的实际办公出口、公网 VPN 出口或反向代理解析出的客户端网段判断。

启用步骤：

1. 先完成反向代理和真实 IP 验证；
2. 写入最小可信代理 CIDR；
3. 写入当前管理员真实出口 `/32` 或 `/128`；
4. 保留一个服务器终端会话；
5. 开启 `TRUSTED_NETWORKS`；
6. 从允许和不允许的网络分别验证。

如果误锁，在服务器交付目录执行：

```bash
./manage.sh admin-access-reset
```

该命令把配置区恢复为仅账户权限并写入审计，不会重置密码或清除配置。

## 6. Docker 与宿主机

交付 Compose 已启用：非特权提升、删除默认 capabilities、仅补回运行所需最小 capabilities、PID 限制、init 进程和停止宽限期。仍需落实：

- 及时安装 Linux 和 Docker 安全更新；
- SSH 禁止密码登录，限制管理来源；
- 交付目录、`data/`、`backups/` 仅运维账号可读；
- 不把 Docker socket 挂入应用容器；
- 不在同机运行来源不明的容器；
- 定期检查磁盘、Docker 日志和备份可恢复性。

## 7. 功能包安全

功能包是甲方授权执行的 Python 代码，不是无害文档。平台提供压缩包校验、非 Web 用户执行、工作目录权限、进程终止和审计，但单机 Docker 不是强对抗沙箱。

只有受信开发人员能上传功能版本。上线前代码审查至少检查：

- 不读取平台/其他客户文件；
- 不执行 shell 和子进程；
- 不建立反向连接或下载执行代码；
- 不关闭 TLS 校验；
- 不把密钥写日志；
- 依赖来源和版本可追溯。

## 8. 事件处置

怀疑入侵时：

1. 在网关隔离公网入口，不急于删除容器和日志；
2. 禁用可疑账号，轮换所有已存客户凭据；
3. 创建完整数据备份并另存；
4. 导出安全审计、运行日志、程序日志和代理日志；
5. 保存主机登录、Docker 事件和时间线；
6. 在干净服务器恢复经确认的备份；
7. 完成根因分析后再恢复业务。

只改登录密码不能处理已经泄露的客户 API 密钥。
