# 备份、恢复与迁移

## 1. 备份范围

`./manage.sh backup` 对整个 `data/` 做停机一致性备份，包括：

- SQLite 数据库及迁移状态；
- 实例密钥和加密材料；
- 功能包、客户数据源和依赖环境缓存；
- 运行日志、程序日志和审计数据；
- 系统更新包、版本目录、数据库回退文件和当前版本指针。

只复制 `fcc.db` 不构成完整备份。缺少实例密钥时，加密配置将无法恢复。

## 2. 创建备份

```bash
cd /opt/feature-control-center/功能控制中心-2.1.2
./manage.sh backup
```

脚本会停止容器、生成 `backups/fcc-data-时间-manual.tar.gz`、生成同名 `.sha256`，然后在原来运行中的情况下重新启动并等待健康检查。

每次备份后，把两个文件一起复制到另一台受控存储：

```text
fcc-data-20260909T120000Z-manual.tar.gz
fcc-data-20260909T120000Z-manual.tar.gz.sha256
```

备份含配置密钥和客户文件，访问权限不应低于生产服务器。不要用聊天软件或公共网盘传输。

## 3. 保留建议

小规模单机建议至少保留：

- 最近 7 天每日备份；
- 最近 4 周每周备份；
- 每次系统更新前备份；
- 每次重大功能/数据源切换前备份。

备份保留策略是运维责任，不受页面中的日志保留天数控制。

## 4. 恢复

先把备份和校验文件放到服务器，再执行：

```bash
./manage.sh restore /安全路径/fcc-data-20260909T120000Z-manual.tar.gz
```

输入 `RESTORE` 后，脚本会：

1. 校验 SHA-256；
2. 停止系统；
3. 再备份当前数据；
4. 拒绝备份中的越界路径、链接和特殊文件；
5. 解压到候选目录；
6. 对候选数据执行应用预检和数据库迁移；
7. 同文件系统切换目录并启动；
8. 健康检查失败时自动换回原数据。

成功后，恢复前目录保留为 `data.before-restore-时间`。业务确认无误后再手工删除。失败候选会保留为 `data.failed-restore-时间`，便于技术人员调查。

## 5. 迁移服务器

1. 记录旧服务器系统版本和架构；
2. 停止业务操作，执行完整备份；
3. 把备份和 `.sha256` 复制到新服务器；
4. 在新服务器解压同版本或受支持的新版本交付包；
5. 执行 `./install.sh` 形成可用空实例；
6. 执行 `./manage.sh restore <备份>`；
7. 检查客户、用户、配置、数据源、任务和日志；
8. 手工运行交付验收示例；
9. 切换域名/代理；
10. 观察一个完整业务周期后再关闭旧服务器。

迁移期间不能让新旧系统同时执行同一客户的定时任务。应先停旧系统，再启新系统的调度。

## 6. 恢复演练

至少每季度在隔离服务器做一次恢复演练，记录：备份文件、校验结果、恢复耗时、登录结果、功能运行结果和发现的问题。没有恢复演练的备份只能证明“文件存在”，不能证明“系统可恢复”。
