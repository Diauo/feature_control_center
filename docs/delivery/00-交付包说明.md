# 功能控制中心 2.1.2 交付包说明

## 1. 交付目标

本系统用于按客户管理并运行 Python 功能。一个账号可管理多个客户；功能、配置、数据源、定时任务和执行日志都带客户归属。平台只负责功能的注册、调度、停止、日志和输入快照，不参与库存同步等业务判断。

本交付包同时包含可部署程序、完整源代码、功能包示例、OZON 实际适配包、运维脚本和操作文档。运行数据不放入交付包，避免把账号、密钥、客户文件或历史日志带到另一台服务器。

## 2. 先看这三个文件

1. `DELIVERY-MANIFEST.json`：版本、交付模式、镜像和功能包清单。
2. `checksums.sha256`：交付包内文件的 SHA-256 校验清单。
3. `docs/delivery/01-Linux一键部署.md`：服务器部署步骤。

## 3. 两种交付模式

`DELIVERY-MANIFEST.json` 的 `deliveryMode` 决定首次部署方式：

- `offline-image`：`images/` 中带当前服务器架构的 Docker 镜像，安装脚本直接载入，不需要在服务器编译系统。
- `source-build`：没有伪造或跨架构冒充的镜像。安装脚本使用同包源代码构建镜像，首次执行需要访问 Docker Hub、GitHub、sqlite.org、npm 和 Python 软件源。

无论哪种模式，管理员只执行同一个入口：

```bash
chmod +x install.sh manage.sh deployment/*.sh
./install.sh
```

脚本会校验文件、保留已有 `data/`、准备镜像、启动 Web/Runner/Scheduler、等待健康检查，并在首次安装时直接打印初始化地址和一次性验证码。

## 5. 随包功能包

- `交付验收示例-2.1.2.zip`：不联网、无第三方依赖，用于验收注册、数据源、实时日志和中文执行报表。
- `功能包起步模板-2.1.2.zip`：供开发人员复制的最小规范模板，包含 `ctx.report` 示例。
- `实时日志稳定性测试-2.1.2.zip`：每 0.3 秒输出一条日志并提交一条测试结果，用于验证任务正常完成、主动终止和报表完整性。
- `OZON库存同步-2.1.2-online.zip`：来自甲方实际脚本，首次注册时在线安装依赖。
- `OZON库存同步-2.1.2-linux-amd64-offline.zip`：仅在清单不为 `null` 时提供，带 Linux x86_64 离线 wheel。其他架构不能使用这个包。

## 6. 数据与责任边界

- `data/` 是唯一的系统持久数据目录，包含 SQLite、客户数据源、功能版本、日志、运行缓存、更新包和更新回退材料。
- 重建容器不会删除 `data/`。执行 `docker compose down -v`、手工删除目录或错误覆盖宿主机文件仍会造成数据损失。
- `backups/` 必须另行复制到与服务器不同的存储。只放在原服务器不算备份。
- 平台确保每次运行绑定当时的代码、配置和数据源修订，并保存脚本通过通用契约提交的逐条结果；业务脚本负责每个商品的成功、失败、无数据判定和失败处理。
- OZON 包没有在真实店铺凭据上执行。上线前业务联调属于必做门槛，不能用平台验收替代。

## 7. 交付验收顺序

1. 按 `01-Linux一键部署.md` 安装。
2. 按 `02-管理员操作手册.md` 完成初始化。
3. 上传交付验收示例并按 `08-交付验收.md` 执行。
4. 执行一次 `./manage.sh backup`，核对备份和校验文件。
5. 完成公网 HTTPS、主机防火墙和配置管理访问门，再接入真实客户。

验收未通过时，不要上传真实密钥和数据源，也不要直接运行 OZON 库存更新。
