# 2.2.0 业务员菜单权限

## 1. 背景与目标

业务员账号需要按账户控制可见功能面：例如仅授权「工作台」的账号只能执行功能、替换数据源；再授权「运行记录」后即可查看运行记录、实时日志和报表。管理员拥有全部菜单；「系统设置」为管理员专属，不参与授权。

权限单元是**菜单**（沿用现有导航项粒度），按账户授予；授权对业务员即时生效，不需要重新登录。

## 2. 菜单注册表

| key | 名称 | 可授予业务员 |
| --- | --- | --- |
| workspace | 工作台 | 是 |
| runs | 运行记录 | 是 |
| schedules | 定时任务 | 是 |
| feature_admin | 功能管理 | 是（含代码上传与配置密钥，授予时自行把控） |
| users | 用户管理 | 是 |
| customers | 客户管理 | 是 |
| audit | 安全审计 | 是 |
| settings | 系统设置 | 否（管理员专属） |

## 3. 数据模型（迁移 0011）

- 新表 `user_menu_grant(user_id, menu_key, created_by, created_at)`，主键 `(user_id, menu_key)`，`menu_key` 带 CHECK 约束
- 管理员不落授权行，代码中等于全部菜单；业务员的授权为**替换语义**（与客户关联一致）
- 迁移回填：升级时给存量业务员授予 `{工作台, 运行记录, 定时任务}`，保证升级前后能力一致
- 新建业务员默认授权 `{工作台, 运行记录}`；服务端校验：只能是可授予集合内的 key、至少一项

## 4. 后端校验（强制）

- `AuthContext` 增加 `menus` 字段：`authenticate()` 时装载（管理员 = 全部菜单；业务员 = 授权行），每次请求实时读取，授权调整立即生效
- 装饰器 `require_menu(*keys)`：管理员直通；业务员按授权校验（多 key 为任一命中），失败返回 403 `MENU_PERMISSION_REQUIRED`
- 端点映射：

| 菜单 | 端点 |
| --- | --- |
| workspace | 客户功能列表（含任一业务菜单放行的只读列表）、数据源元信息/替换/下载、创建运行 |
| runs | /api/runs 全部（列表/详情/事件/流/报表/日志下载/停止） |
| schedules | /api/schedules 全部 |
| feature_admin | /api/admin/feature-definitions、功能包上传、依赖重试、默认数据源下载、切换版本、复制、运行策略、配置读写 |
| users / customers / audit | 对应的 /api/admin 端点 |
| settings | 保持不变（require_admin，管理员专属） |

- 只读功能列表端点同时服务于工作台、运行记录、定时任务和功能管理页面，按「任一相关菜单」放行
- 服务层同步改为菜单校验（`identity` / `features`），业务数据的客户范围隔离继续生效
- 管理区路由继续叠加 `require_management_network`（可信网络门）

## 5. 前端

- 会话装载 `menuKeys`；导航按授权渲染；路由 `meta.menu` + 守卫（无权限时重定向到首个已授权菜单）
- 用户管理：创建/编辑业务员时勾选菜单（系统设置不出现），列表展示授权，默认勾选「工作台 + 运行记录」
- 工作台：移除「上传功能包」与「配置管理」；点击运行时按有无「运行记录」权限决定是否跳转实时日志（无权限时提示「任务已提交」并停留原页）

## 6. 同批次权责整理

- 工作台职责收敛为：执行功能、替换/下载数据源
- 「配置管理」移入功能管理（复用原配置抽屉；功能卡片上直接打开）
- 功能管理中既有的上传与版本管理能力不变
